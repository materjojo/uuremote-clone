# 按需构建管理

用户已明确授权把 `materjojo/uuremote-clone` 原仓库转为公开。工作流仅使用公开仓库免费的标准 GitHub-hosted runner；不使用 larger runner，不在本地编译应用。

## 自动选择

- 仅 README / docs 变更：不启动工作流。
- Android 源码/资源/构建配置：只构建 Android。
- Windows 源码/资源/项目配置：只构建 Windows。
- Swift 源码/Package/打包脚本：只构建 macOS。
- 共享 core / proto / C ABI：验证 Linux 核心并构建所有实际消费者。
- 单个平台原版库分片：只构建对应平台。
- 纯逆向 Evidence 更新：最多执行便宜的静态检查，不编译应用。
- workflow 和选择逻辑本身修改：首次全端验证。

选择逻辑是 [ci_plan.py](../scripts/ci_plan.py)，有针对平台隔离、共享依赖、多提交区间和手动选择的 [测试](../scripts/test_ci_plan.py)。比较 push 的完整 before..after，重命名同时计算原路径与新路径。

## 避免重复

Windows 的 C++ 测试、真实 DLL 冒烟、C# 绑定和应用打包合并到同一个 job，使用同一份 gvpb.dll；CMake object library 让静态库和 DLL 共用已编译对象。macOS 原来的单独核心 job 也合并到 app job，仅在共享 native 代码变化时执行 C ABI 检查。Swift 测试已构建可执行文件时不再重复执行 swift build。

每个平台只恢复自身原版库；Android 不解压桌面库。依赖使用 Swift 下载缓存、NuGet 缓存和 Gradle 自身缓存。产物保存 7 天，避免长期累积大型调试包。

并发取消按平台分组：新 Windows 构建只取消旧 Windows 构建，不取消无关平台正在进行的任务。

## 手动构建与结果解释

`workflow_dispatch` 的 target 可选 all / core / macos / windows / android。修复哪个平台就选择哪个平台；只有共享实现或工作流改变才需要全端构建。

未变更的平台跳过编译，不能将当前运行中的 skipped 写成新构建成功；下载该平台最近一次成功且其输入未变化的产物。真实库版本检查通过也不等于媒体会话、硬件路径和 UI 已完成验收。
