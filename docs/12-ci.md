# 按需构建管理

用户已明确授权把 `materjojo/uuremote-clone` 原仓库转为公开。工作流仅使用公开仓库免费的标准 GitHub-hosted runner；不使用 larger runner，不在本地编译应用。

## 自动选择

- 仅 README / docs 变更：不启动工作流；独立路径运行/截图的固定结果写入 `analysis/ci/latest-independent-results.json`，不把旧产物误写成当前构建。
- Android 源码/资源/构建配置：只构建 Android。
- Windows 源码/资源/项目配置：只构建 Windows。
- Swift 源码/Package/打包脚本：只构建 macOS。
- 共享 core / proto / C ABI：验证 Linux 核心并构建所有实际消费者。
- 单个平台原版库分片：只构建对应平台。
- 纯逆向 Evidence 更新：最多执行便宜的静态检查，不编译应用。
- 原版运行时 manifest / 分片索引：比较前后提交的实际平台记录，Windows 增加组件只重建 Windows；公共元数据改变则验证所有相关平台。
- workflow：只修改单个平台 job 时只重建该平台；公共触发器、权限、plan 或未知结构改变时保守验证全端。

选择逻辑是 [ci_plan.py](../scripts/ci_plan.py)，有针对平台隔离、共享依赖、多提交区间和手动选择的 [测试](../scripts/test_ci_plan.py)。比较 push 的完整 before..after，重命名同时计算原路径与新路径。

## 避免重复

Windows 的 C++ 测试、真实 DLL 冒烟、C# 绑定和应用打包合并到同一个 job，使用同一份 gvpb.dll；CMake object library 让静态库和 DLL 共用已编译对象。macOS 原来的单独核心 job 也合并到 app job，仅在共享 native 代码变化时执行 C ABI 检查。Swift 测试已构建可执行文件时不再重复执行 swift build。

每个平台只恢复自身原版库；Android 不解压桌面库。依赖使用 Swift 下载缓存、NuGet 缓存和 Gradle 自身缓存。产物保存 7 天，避免长期累积大型调试包。

并发取消按平台分组：新 Windows 构建只取消旧 Windows 构建，不取消无关平台正在进行的任务。

## 手动构建与结果解释

`workflow_dispatch` 的 target 可选 all / core / macos / windows / android。修复哪个平台就选择哪个平台；共享实现或工作流公共部分改变时需要全端构建。

未变更的平台跳过编译，不能将当前运行中的 skipped 写成新构建成功；下载该平台最近一次成功且其输入未变化的产物。真实库版本检查通过也不等于媒体会话、硬件路径和 UI 已完成验收。

Windows 原版 detector 的发布目录观察已在 [44881938396](https://github.com/materjojo/uuremote-clone/actions/runs/44881938396) 通过：只选择 Windows，14 个 batch 完成但 112 条 RESULT 的 probe flag 均为 0，不能写成硬件成功。`Native-ABI-windows` 保留 stdout/stderr 原始字节和输入身份。隔离的原版 DLL Initialize/Finalize 探测同样限定在该 Windows job，各角色单独进程、UTF-16 路径、60 秒上限；报告即使失败也随 native artifact 上传，不等同于应用媒体集成。

Windows 的 loopback room 探测也只在此 job 运行；`--room-fixture-ca` 明确表示对子进程原生 store 的测试 CA 插桩，报告先保留普通 TLS 拒绝，再记录 transport 和客户端事件，不回复业务入房。`576b43b` / [44891638984](https://github.com/materjojo/uuremote-clone/actions/runs/44891638984) 两角色通过该受限检查；这不是生产房间接入或原库默认信任证据。该次 Windows 发布包为 [14702575767](https://github.com/materjojo/uuremote-clone/actions/runs/44891638984/artifacts/14702575767)，其它平台均 skipped。

后续 `2fb1d6a` / [44894436889](https://github.com/materjojo/uuremote-clone/actions/runs/44894436889) 进一步通过两角色独立 room_info 正/负对照及生产 C# 房间绑定检查，报告在 Native-ABI-windows 中以 `streamer-roominfo-windows.json`、`streamer-roominfo-empty-windows.json` 和 `streamer-managed-rooms-windows.json` 保存。编译后的委托生命周期、再次开房和活动房间 Dispose 均在 runner 执行；父记录器和测试工程保留 explicit fixture trust 标记。最新该次 Windows ZIP 为 [14702439833](https://github.com/materjojo/uuremote-clone/actions/runs/44894436889/artifacts/14702439833)，其它平台 skipped。

Android 的 `assembleDebug` 依赖 `testDebugUnitTest`，因此新增 JVM 测试会随 Android 构建执行，不需要为每次增加测试修改全局 workflow。当前会话测试使用替身 StreamerController；检查生命周期和参数转发，不加载原版 ARM64 native 库。Android 独立 native peer 测试则运行在 x86_64 Android 11 模拟器，验证合成视频、控制和候选策略；它不等价于 ARM64 原版库运行。Windows 发布包的 `Windows published UI capture` 工作流现在可在成功 build 后自动取包、启动真实 MainWindow，并保存截图或异常副本。
